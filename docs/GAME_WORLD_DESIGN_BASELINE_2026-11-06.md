## 1. Project Vision

Transform StarLiz Academy's existing Coding Learning experience into an interactive, connected educational world where children learn programming by completing meaningful activities.

Instead of only moving an object around a grid to collect a star, children will prepare pizzas, build robots, operate farms, manage traffic, explore space and care for animals.

The Game World will preserve the educational infrastructure already developed, including the existing coding editors, curriculum, lesson workflow, learning assessments, student records and access controls.

Its purpose is to improve the learner experience and provide room for future expansion without rebuilding the original platform.

## 3. The Connected Game World

### Central Hub — StarLiz Inventors Academy

The central hub provides access to the world map, missions, coding progress, personal projects, Coding Clubhouse and AI companion.

Children can walk between locations or use the map for direct travel.

Guided lessons can open an assigned coding mission without requiring the child to navigate through the world first.

### Six Game Locations

**1. Pizza Restaurant**

Children become coding chefs and restaurant inventors.

Activities include programming ingredient preparation, following recipes, processing customer orders, controlling ovens and automating deliveries.

Concepts develop from sequences to loops, conditions, reusable procedures and more advanced automation.

**2. Robot Factory**

Children design, control and experiment with robots.

Activities include navigation, obstacle avoidance, sensor responses, robot construction and task automation.

Programmed robots may later become useful in other locations.

**3. Happy Farm**

Children operate a smart farming environment.

Activities include planting, irrigation, harvesting, weather monitoring and automated farm machinery.

Coding can control simulated sprinklers, sensors and harvesting routines.

**4. Traffic City**

Children develop transportation and road-safety systems.

Activities include controlling traffic lights, managing intersections, routing vehicles, coordinating deliveries and responding to traffic conditions.

The focus includes logical decisions, timing, conditions and algorithms.

**5. Space Centre**

Children become space-technology inventors.

Activities include programming spacecraft navigation, exploration robots, simulated rocket systems, scientific missions and resource collection.

Advanced missions introduce more complex programming problems.

**6. Pet Care Centre**

Children create systems that help care for virtual animals.

Activities include feeding routines, environmental controls, monitoring systems and intelligent care equipment.

Missions introduce sequences, conditions, events and automation through age-appropriate animal-care simulations.

### Cross-Location Inventions

Children can apply inventions in different parts of the world.

A robot developed in the Robot Factory might assist at the Pizza Restaurant or Farm. Traffic City could manage transportation between destinations.

These connections reinforce that programming skills can solve different kinds of problems.

## 4. Guided Lessons and Free Practice

### Guided Lesson Mode

This mode operates through StarLiz's existing curriculum and lesson system.

An authorised coding lesson launches a suitable game mission with defined educational objectives.

The mission produces assessment evidence through the existing learning and progress services.

Teacher-assigned activities, prerequisites, mastery requirements and publication restrictions remain authoritative.

### Free-Practice Game World

Children may explore all six locations independently and complete available practice missions.

They can experiment, create inventions, customise their world and build coding projects.

Practice achievements are recorded separately from formal curriculum results.

**Free-practice success must never automatically mark a formal lesson as completed or mastered.**

The avatar, AI companion and permitted personalisation can remain consistent across both modes.

## 5. Coding and Debugging Experience

The established My Program experience is retained and expanded.

Children begin using the current visual block-programming approach. As their skills develop, StarLiz can introduce readable code and then supported text-programming activities.

The progression to JavaScript is part of the approved design but must be checked against the existing implemented language support before technical work begins.

A shared Game World integration layer converts supported coding actions into visible game behaviour.

The adaptive workspace will provide editing, execution, reset, replay, debugging and clear feedback.

During debugging, children can see how their instructions affect the environment, identify incorrect steps and revise their program.

The AI companion provides progressively stronger hints without unnecessarily revealing complete answers.

---

## 6. Learning Progress and Assessment

The approved assessment system differentiates:

- Completion with assistance.
- Independent completion.
- Demonstrated mastery across suitable challenges.
- Concepts requiring further practice.

The learning journey combines curriculum progress, coding skills, achievements, saved projects and recommendations.

Teachers retain authority over formal assessments.

Children may replay completed challenges, explore alternative solutions and practise previously learned skills.

The Coding Game World must not replace existing assessment contracts or delete previous results.

---

## 7. Persistent World, Clubhouse and Rewards

Each learner has a private world state and Coding Clubhouse.

Achievements can unlock cosmetic items, decorations, new equipment and building improvements.

World development reflects learning progress rather than purchases.

Saved state includes relevant personalisation, earned upgrades, coding projects and permitted simulation progress.

When a learner leaves, active missions pause. Only safe, explicitly supported background activities may progress.

Returning learners receive a brief summary without being punished for time away.

No paid rewards, randomised purchases or gambling-style mechanics are part of this design.

---

## 8. Accessibility, AI and Safeguarding

The world will support readable text, high-contrast presentation, reduced motion, simplified instructions and appropriate device controls.

The AI companion communicates through text, speech bubbles and visual demonstrations, with no microphone requirement or spoken dialogue.

NPC behaviour must remain age-appropriate and constrained by the educational experience.

The Game World remains individual and private.

No multiplayer, public chat or contact with strangers is permitted.

Existing parent, teacher, administrator and school access boundaries must be retained.

Where teachers provide additional learning assistance, the established authorised Human Support workflow remains the governing system.

---

## 9. Content Management Studio

The approved Coding Game Content Studio will provide authorised educational administrators with controlled content-management features.

Its intended scope includes mission definitions, chapters, curriculum mapping, dialogues, rewards, lesson previews, draft review, publishing and content version management.

Teachers can assign approved activities using their existing permissions.

The core game execution engine and security-sensitive logic remain developer-controlled.

Content administrators will not receive unrestricted executable-code publishing powers.

Existing curriculum publication restrictions must remain effective until separately approved changes are made.

---

## 10. Architectural Integration

### Preserve the Existing Platform

StarLiz Coding Learning remains the foundation.

The modular upgrade should connect to existing:

- Student authentication and permissions.
- Curriculum and lesson structure.
- Blockly and supported coding editors.
- My Program execution and debugging.
- Assessment and learning progress.
- Saved projects and student records.
- AI tutoring and authorised Human Support.
- Parent, teacher and administrator portals.

### Add Modular Game World Capabilities

The new layer will introduce game environments, simulation state, animated actions, NPC interactions, navigation, personalisation, mission configurations and future-game extension points.

The exact module interfaces and compatibility requirements must be determined by a read-only audit of the actual repository before implementation.

Existing working logic should be reused rather than duplicated.

### Future Expansion

The architecture must allow additional coding environments, challenges and appropriate programming concepts to be introduced without rebuilding the entire Game World.

---

## 11. Consolidated Delivery and Production Protection

The approved delivery strategy is **one consolidated upgrade**.

This does not prohibit internal engineering milestones or testing checkpoints. It means development should be coordinated as one integrated programme, with compatibility testing across the complete platform before release.

Production protection is mandatory:

- No migration reset.
- No destructive database changes.
- No deletion of existing curriculum, projects or student progress.
- No replacement of existing working coding infrastructure merely to introduce game functionality.
- No unapproved publication or alteration of curriculum.
- No production deployment without separate authorisation.
- No unrelated feature changes.
- Existing production and local working baselines must remain protected.

Any necessary future schema additions must be additive, reviewed and separately authorised before application.

## 12. Final Review and Outstanding Technical Verification

Exact mission counts, detailed individual lesson mappings, graphical assets, performance budgets and the practical implementation of certain simulation features remain to be specified or validated.

**No implementation instructions are authorised by this design document.**

The next milestone is final design acceptance and compatibility review, preserving the existing StarLiz Coding Learning investment throughout.



## Final review — the key protection

The most significant decision is **Decision 39: Modular Extension**\. That means the Game World should sit on top of the substantial Coding Learning work already completed, rather than requiring new editors, another curriculum system or a replacement database.

Decision 40 also means we will coordinate the whole upgrade rather than deploy unfinished games to production one by one.

There are still technical details to validate against the actual VS Code repository, particularly existing coding interfaces, curriculum mappings, publication rules and the rendering approach for the 2.5D world.
