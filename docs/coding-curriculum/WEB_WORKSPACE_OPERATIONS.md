For a static HTML/CSS activity, a fixed inspection program parses the supplied markup and stylesheet as data inside the isolated runtime. For an interactive JavaScript activity, the learner program and its event sequence execute first; its exported inert document is then inspected in a **fresh container**. The second process does not use query methods or grading metadata supplied by the learner program. Actual query-method replacement and stylesheet inspection passed in the uniquely named `artifacts/coding-runner/dom-inspection-*` evidence directory.

The pinned DOM library has stylesheet parsing and selector matching, but no `getComputedStyle` browser layout engine. The actual capability result is retained at `artifacts/coding-runner/dom-capabilities-9aa0b125-e339-4df7-a543-b088bbd638a6/result.json`. Foundation inspection resolves simple type, class, ID and combinator selectors, declaration priority, inline declarations, supported inherited text properties and explicit colours. It reports unsupported selectors, properties and at-rules instead of claiming to verify them. Font and padding metrics require explicit pixel values. It does not certify browser geometry, responsive layout, full CSS support or comprehensive accessibility.

Contrast calculations retain the unrounded ratio for assessment. The normal-text requirement in these foundation activities uses [W3C's 4.5:1 minimum contrast explanation](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). A display rounded to two decimal places is not the assessment value.
