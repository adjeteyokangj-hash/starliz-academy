# England alignment and StarLiz extension matrix

Status: **planned coverage**, not delivered or accredited coverage. Requirement codes are StarLiz shorthand, not DfE identifiers.

Reference: [DfE computing programmes of study, key stages 1–4](https://www.gov.uk/government/publications/national-curriculum-in-england-computing-programmes-of-study/national-curriculum-in-england-computing-programmes-of-study), retrieved 2 November 2026. England is the academic reference; no alignment claim is made for Scotland, Wales or Northern Ireland. Programmes specify key-stage outcomes; annual sequencing here is StarLiz's proposed design.

For each requirement, the primary evidence IDs below fall within its key stage. Later reinforcement cannot repair a missing end-of-key-stage entitlement. A named topic alone is insufficient: delivery requires the linked task, negative case and independent evidence in the inventory.

## StarLiz extensions

| Extension | Original StarLiz focus | Examples |

| X-AI — AI and data judgement | Training/test separation, bias, uncertainty, provenance and responsible evaluation. | Y6.18, Y9.18, Y11.12 |

| X-SE — Software engineering | Specifications, version history, automated tests, reviews, architecture and maintenance. | Y8.24, Y9.24, Y10.06, Y10.12, Y10.24, Y11.06 |
| X-API — APIs and service contracts | Fixture-backed requests, response validation, errors and service boundaries. | Y8.12, Y10.12, Y10.24, Y11.06 |
| X-PORT — Portfolio and professional practice | Private evidence, iteration, accessibility, user feedback and reasoned evaluation. | Y1.06, Y1.12, Y1.18, Y1.24, Y2.06, Y2.12 |

Robotics and AI contribute to existing modelling, data and judgement outcomes; their particular treatment is a StarLiz extension. APIs, engineering workflows and defensive security add practical depth. These units remain inside Coding and do not instantiate additional Skills Labs.
